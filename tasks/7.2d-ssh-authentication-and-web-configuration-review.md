# Task 7.2D: SSH authentication and web configuration review

[Back to portfolio](../README.md)

**Tools and concepts:** Metasploit SSH login scanner, Linux identity, Apache, legacy cross-domain policy

**Source:** supplied SIT379 portfolio, physical PDF pages 155-161 (counting the first reflection page as page 1).

**Assessment snapshot:** Complete. This describes the uploaded portfolio, not a later or final grade.

## Objective
Validate controlled SSH access and inspect the resulting host's web configuration.

## Task 1: authentication test
Created candidate username/password lists for the lab, used the SSH login scanner and opened the resulting session. The submission reports a successful session and checked the identity as root. Real-world breached credentials and credential lists are not included in this repository.

## Task 2: configuration analysis
- Confirmed Apache was running.
- Inspected the default site configuration.
- Identified `/var/www` as the configured document root.
- Reviewed a `ClientAccessPolicy.xml` file described as permitting broad cross-domain access and request headers.

## Findings and limitations
Root identity on that session establishes high privilege for the lab host; it does not prove reuse or compromise elsewhere. The policy finding concerns a legacy client mechanism, particularly Silverlight. It is not interchangeable with modern browser CORS, and a Silverlight policy file should not be assumed to govern Flash clients, which use their own policy mechanism.

The readable transcription loses wildcard characters, so the exact XML should be checked against the original screenshot before applying a field-by-field configuration fix. Broad policy permissions indicate potential exposure, not proof of a completed cross-origin data theft.

## Defensive recommendations
Remove obsolete client-policy features where unnecessary, restrict origins and resources where retained, and validate current client behaviour. Harden SSH with appropriately configured keys, account restrictions and monitoring; avoid direct root login and reused passwords.
