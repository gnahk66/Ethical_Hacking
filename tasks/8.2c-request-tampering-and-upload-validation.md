**Tools and concepts:** Browser developer tools, OWASP ZAP, HTTP methods, business logic, MIME types

**Source:** supplied SIT379 portfolio, physical PDF pages 173-179 (counting the first reflection page as page 1).

**Assessment snapshot:** Complete. This describes the uploaded portfolio, not a later or final grade.

## Objective
Test whether the server enforces security properties independently of the normal browser interface.

## Task 1: password change over GET
Changed the client form method and observed a password change through GET. Sensitive query values can appear in history and logs. The finding is that the server accepted an unsafe state-changing request, not that editing HTML changes server security by itself.

Use an authenticated POST endpoint over HTTPS, validate authorisation, add CSRF protections and require suitable reauthentication. POST alone does not supply those controls.

## Task 2: negative basket quantity
Intercepted a basket update and changed quantity from 1 to -15. The source records the altered basket and identifies insufficient server-side range validation. Negative values can affect order calculations; the specific financial impact still depends on downstream processing and was not established beyond the lab display.

Validate a bounded positive integer on the server and recompute totals from trusted prices.

## Task 3: upload metadata
Changed the multipart file's claimed MIME type while retaining an HTML filename, then used the application's inclusion feature. This investigated trust in client-supplied content metadata. Upload acceptance, browser rendering and server-side execution are separate outcomes and should not be conflated.

Use extension and content allowlists, inspect actual content, generate server-side names, constrain file size, prevent execution and isolate uploaded active content from the application's origin.

## Reflection
Client validation helps usability. The enforcement point is the server, which must assume requests can be edited or generated outside the intended interface.
