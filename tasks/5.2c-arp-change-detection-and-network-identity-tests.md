## Objective
Build a basic defensive ARP monitor and compare related network-manipulation tools.

## Task 1: ARP detector
The submitted Python/Scapy script inspected ARP replies, recorded an IP-to-MAC mapping on first observation and printed an alert when later replies changed that mapping. It then updated the stored value. The submission reports alerts during an Ettercap lab test and acknowledges generative-AI assistance and research sources.

This detects changes, not malicious intent. A poisoned first observation becomes the baseline; legitimate failover or address reassignment can also alert. Updating after each change can lose the trusted reference and produce repeated oscillation alerts. A production design would need trusted bindings, interface selection, timestamps, durable logging and handling for legitimate network changes. No new production-ready detector is claimed here.

## Task 2: DNS spoofing comparison
Repeated the on-path setup with separate ARP-poisoning processes and dnsspoof. The recorded run showed outbound queries and a DNS failure, with no completed forged-answer/redirection evidence. It must be reported as incomplete, rather than a successful equivalent of the previous Ettercap test. Fewer separate processes made Ettercap easier to manage in this lab; that is not a universal performance benchmark.

## Task 3: MAC address change
Changed the Kali interface address to a selected vendor-prefixed value and checked the configured and permanent addresses. A vendor prefix does not establish hardware identity or bypass authentication by itself.
