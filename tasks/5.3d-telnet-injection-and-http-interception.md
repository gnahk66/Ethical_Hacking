## Objective
Examine the evidence needed to claim TCP-session manipulation and HTTP-request modification.

## Tasks 1-2: Telnet investigation
Inspected a plaintext Telnet session and constructed a lab packet using the connection's address/port tuple, sequence state and an injected command. The write-up explains a follow-up acknowledgement and includes a capture containing the injected data.

The evidence supports construction/transmission of a packet. It does not conclusively establish the complete echo/acknowledgement requirement: the portfolio explicitly records difficulty showing that output. A captured injected command alone does not prove server execution, acceptance or full session takeover. Wireshark relative and absolute sequence numbers can also look different without being erroneous.

## Task A3: HTTP interception
Configured Windows to use ZAP as an explicit proxy, confirmed requests appeared in ZAP, set a breakpoint and modified a test request. The resulting browser behaviour was consistent with the changed destination. This is a configured-proxy exercise; it does not establish transparent compromise of an arbitrary HTTPS session.

## Task A4: protective controls
Use SSH instead of Telnet, HTTPS with certificate validation, strong session identifiers, session regeneration at authentication, expiry and logout invalidation. Secure, HttpOnly and SameSite cookie attributes address different exposure paths and should be applied according to application needs.

## Reflection
Separate packet creation, server acceptance, command execution and acknowledgement in the report. Each needs its own evidence; explanatory code comments are not substitutes for captured outcomes.
